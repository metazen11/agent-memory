AgentMemory + Anvil: Strategic Advantages

Executive summary of current capabilities, active work, and what additional compute/VRAM unlocks for coding model quality, parallel agents, and local AI ownership.

Ownership boundary: This document describes independent R&D work outside WFCA scope. No IP transfer, assignment, or licensing is implied by this summary.

Local-first AI engineering stack Cross-session memory + orchestration Fine-tuning / RL data pipeline Multi-host integration (Claude/Codex/Gemini)

What We Have Built

1) Durable Memory Platform (AgentMemory)

  • Persistent memory service for coding agents on PostgreSQL + pgvector with hybrid semantic + full-text search (RRF fusion).
  • Embedding pipeline in production: sentence-transformers embeddings (768-dim) indexed with HNSW for fast retrieval.
  • Captures tool calls, responses, and session context; converts activity into reusable observations and lessons.
  • Exposes both REST API and MCP interfaces for agent interoperability.
  • AgentMemory MCP tools available now: memory_search_guide, search, timeline, get_observations, save_memory, create_lesson, search_lessons, export_training_dataset, training_export_guide.
  • Supports project-scoped and global memory retrieval with path-aware filtering.
  • Training dataset export surfaces: raw tool ledger, SFT, trajectory, and preference datasets with reward/error filtering.

What We Have Built

2) Autonomous Runtime + Prompt Pack (Anvil)

  • Host-agnostic autonomous pipeline with explicit stages: INIT → PICK → PLAN → DEV → CODE_REVIEW → TEST → REVIEW → PR → REPORT → IMPROVE.
  • Task adapters for local todo backlogs and GitHub issues.
  • Specialist agents (review/security/perf/docs/compliance/etc.) and resumable run state.
  • Tool-calling inventory implemented in runtime: list_files, read_file, read_file_full, write_file, edit_file, insert_after, insert_before, delete_with_anchor, replace_block, glob_search, grep_search, bash_run, fetch_url, plus graph-mode done/search_memory.
  • Tooling layer with workspace sandboxing, secret masking, security deny lists, and controlled file/search/shell/web operations.
  • Local model runtime with backend flexibility: local GGUF, LM Studio, OpenAI, Anthropic, MLX.

What I’m Working On Now

  • Unified dataset export workflow so agents can self-serve training corpora via API and MCP.
  • Training guidance/primer endpoints for LLMs to collect clean SFT and RL datasets safely.
  • Tighter linkage from tool calls → observations → rewards for better trajectory and preference learning.
  • Operational hardening to scale from single-agent execution to coordinated multi-agent runs.
  • Improving quality controls: filtering failures/problematic traces and preserving high-signal examples.

Business Value Today

  • Compounding productivity: memory turns solved tasks into reusable institutional knowledge.
  • Higher engineering consistency: codified review/test policies improve quality and reduce regressions.
  • Faster onboarding: new contributors/agents can retrieve project decisions and patterns immediately.
  • Model improvement loop: production interactions become training assets instead of wasted telemetry.
  • Risk reduction: local control over data and model behavior reduces external dependency exposure.

Real-World Constraint: Shared Workstation Load

  • Current development happens alongside heavy desktop apps (IDEs, database tools, meetings, browser stacks), so available unified memory for inference is often much lower than nominal hardware capacity.
  • This reduces practical concurrency for local agents and can force fallback to smaller models during business hours.
  • Operational answer: tiered execution — interactive work on local baseline models, heavy inference/training/evals in scheduled windows or on dedicated compute when available.

Security Roadmap (HIPAA-Aligned Starting Point)

Control Area Initial Implementation Outcome
Encryption in transit HTTPS reverse proxy (Caddy/Nginx), TLS 1.2+, HSTS, HTTP→HTTPS redirect Encrypted API/model traffic end-to-end
Access control API key or JWT auth for endpoints; least-privilege service accounts Controlled system access and reduced lateral risk
Network boundary Private LAN/VPN-only access, no public exposure by default Smaller attack surface
Sensitive data handling Redaction rules, constrained logging, retention/deletion policy Reduced data leakage and compliance readiness
Auditability Audit trails for exports/access/admin actions Traceability for governance and investigations

Goal is HIPAA-aligned engineering controls first; formal HIPAA compliance additionally requires administrative/process controls and legal frameworks.

Wi-Fi-First Secure Deployment (No Wired Network Required)

  • Start on trusted WPA2/WPA3 network and private addressing only.
  • Use overlay networking (e.g., Tailscale) for authenticated, encrypted device-to-device access.
  • Enforce HTTPS + auth on all service endpoints even inside private network segments.
  • Apply host firewalls/IP allowlists so only authorized devices reach inference and memory services.

Why Local Development Matters (Strategic Advantages)

  • Privacy and compliance: sensitive source code and telemetry remain under internal control.
  • No hard vendor lock-in: backends and hosts can be swapped without rewriting the workflow stack.
  • IP ownership: prompts, memory, datasets, and adapters remain proprietary assets.
  • Lower long-term cost curve: less dependence on external per-token pricing for core internal workflows.
  • Explainability and control: we can inspect pipelines, policies, tools, and learned behavior end to end.
  • Faster experimentation: immediate loop from usage telemetry to training data to tuned model behavior.

Recommended Next Investments

  3. Add agent-swarm scheduler controls (priority, budget, and failure recovery policies).
  4. Expand evaluation harness (task success rate, latency, cost/task, defect escape rate).
  5. Institutionalize governance dashboards for memory quality, training quality, and policy adherence.
