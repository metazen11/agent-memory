# v4 — multi-turn LoRA training run

**Date:** 2026-05-18
**Status:** ✅ SHIPPED as production tool-call model (replaces v1 + v3)

## Goal

Fix the v3 tool_response adaptation regression. v3's dataset was 100%
single-turn (4-message: `system → user → assistant(tool_call) → tool`),
so the model never learned the `tool → assistant` transition. In live
agentic use, v3 re-emitted the same tool_call after seeing tool_response
instead of grounding a text answer.

## Dataset (v4)

Source: `mem_tool_calls` (retention_class='backfill_jsonl') joined to
follow-up assistant turns extracted from `~/.claude/projects/**/*.jsonl`.

| Train (final) | 20,931 |
| Valid (final) | 1,283 |
| Tiny train / valid | 200 / 30 |
| Zero-label rows after Fix #10 | 0 |

Multi-turn extension: when the source jsonl shows an assistant text turn
following a tool_response, the row is extended to:

```
system → user → assistant(tool_call) → tool(response) → assistant(text)
```

The trailing assistant text is included in the label mask (loss is
computed on the post-tool-response reasoning).

## A/B vs v1 + v3

Two A/B passes were run; the first used a llama-cli-based harness that
contaminated stdout with banner / ASCII-art / control characters and
produced garbage scores. The corrected harness uses llama-server's HTTP
API directly.

**Multi-turn adaptation, 10 scenarios via llama-server :9099:**

| Model | N | Regression | NewCall | TextAns | Adaptation |
|-------|---:|-----------:|--------:|--------:|-----------:|
| v1 (qwen2.5-3b-q4km, shipped) | 10 | 1 | 8 | 1 | 90% |
| v3 (qwen3-4b-q6k, retracted) | 10 | 3 | 7 | 0 | 70% |
| **v4 (qwen3-4b-q6k, this run)** | **10** | **0** | **0** | **10** | **100%** |

Adaptation = % of turn-2 responses that either emitted a *different* tool_call
or gave a grounded text answer (vs re-emitting the same tool_call).

## Lessons learned

1. **Multi-turn dataset extension is the v3 regression fix.** 40% multi-turn
   rows in v4 was sufficient to bring adaptation from 70% (v3) to 100%.

2. **A/B harness must use llama-server, not llama-cli.** llama-cli (b1-d132f22)
   prints ANSI banner + spinner + ASCII art on stdout unconditionally, even
   with `--log-disable --simple-io`. This contaminates parsed responses and
   produces invalid metrics. llama-server's HTTP API returns clean JSON.

3. **Fix #10 zero-label gate runs at MAX_LENGTH=1024 (full tier) but tiny tier
   uses MAX_LENGTH=512.** The tiny split now filters separately at 512 to
   avoid trainer-assertion fires on tiny smoke tests.

4. **anvil model set --path** updates config but doesn't override LM Studio
   when it's running. To A/B GGUFs directly, use llama-server per-model.
